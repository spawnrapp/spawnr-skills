# Changelog

## Unreleased

- The protocol's refusal table lists two more 409s. `APPROVAL_REQUIRED`: an agent key moved a task to `done` (or another terminal status) and the workspace's approval policy wants a person's sign-off first; submit the work for approval (`POST /api/v1/tasks/{task_id}/approval-requests`, or `spawnr_submit_for_approval` over MCP) and wait for the decision instead of retrying. `agent_not_in_workspace`: a claim of a task in a workspace the agent is not linked to; take another task or ask a person to add the agent. The skills now call the table the main refusal codes, not every one. Docs only; nothing breaking.
- **spawnr-skills#25** — The openclaw docs now say what the product and its scripts do. An agent key starts with `spawnr-`; the docs no longer claim a length or a live/test prefix. The Claude Agent SDK sample uses `query()` with `ClaudeAgentOptions`, with the skill copied to `.claude/skills/` and `"project"` in `setting_sources` so it loads. The README no longer says `poll_tasks.py` claims nothing on `bug/default` boards (it claims a `triaged` bug through `triaged -> fixing`; a `new` bug waits for a person to triage it, since only an Owner, Admin or Manager may move `new -> triaged`), and the `SKILL.md` loop moves a task to its workflow's active status instead of a hardcoded `in_progress`. Key rotation points to Agents, the agent, Connect, "Rotate key & reveal", or `spawnr agent rotate-key <agent-id>`, and says rotating disconnects every client using the old key. The API reference no longer lists per-plan daily caps (they depend on the plan; see the pricing page), the protocol's refusal table lists 422 `summary_required`, and every example uses one placeholder host, `https://app.example.com`. Docs only; nothing breaking.
- **spawnr-skills#24** — Until the local MCP server (`spawnr-mcp`, not on PyPI yet) is published, the docs point an MCP client at the hosted endpoint, your Spawnr host root plus `/mcp`: the agent sends its API key in the `X-API-Key` header for the agent tools, and an OAuth sign-in connects a person with the user tools. The Python example (`python-flow.md`) no longer installs from a private checkout, connects with the agent key, and drops the `spawnr_auth` and heartbeat calls the hosted endpoint does not offer. `setup.sh` ends with the hosted `/mcp` line instead of the `spawnr_list_tasks` and `spawnr_auth` lines, which it keeps for `SPAWNR_LOCAL_DEV`, and its pip fallback installs into an active virtualenv instead of failing on `--user`. The openclaw README's copy commands start with `mkdir -p .claude/skills`. Nothing breaking.
- **spawnr-skills#18** — `SPAWNR_API_URL` now means the same thing for openclaw's `spawnr_client.py` and `poll_tasks.py` as for the `spawnr` CLI: the server address, e.g. `https://app.example.com`. The scripts add `/api/v1` themselves and accept a trailing `/api/v1` on the value, so existing openclaw setups keep working and one value in the environment serves both tools (before, each tool 404'd with the other's value). The openclaw README, `SKILL.md` and the Coder to Tester example show the server-address form. `AgentTaskTracker/docs/user-guides/openclaw-onboarding.md` and the in-app Docs page "Using the scripts without Claude" still teach the `/api/v1` form; that works, and their update is a follow-up in the monorepo.
- **spawnr-skills#17** — The `spawnr-mcp` skill has a "Tasks from a routine" section: `routine_id` and `routine_name` on `spawnr_list_tasks` / `spawnr_show_task`, a routine task arrives already assigned to you (start it, don't claim it), close it so the routine creates its next task, and every routines route is people-only (403 `AGENT_NOT_PERMITTED`, AgentTaskTracker#2854).
- **spawnr-skills#23** — The README opens with what Spawnr is ("A task board for your AI coding agents."), what the skills let an agent do, what you need (a Spawnr account and, for the agent to work as itself, its API key) and the MIT licence. The note on where the skills came from is gone, and the Tests section is now a short Contributing section with this repo's two checks. The `spawnr` skill is titled "Spawnr: a task board for your AI coding agents" and its tagline says it is the CLI skill.
- **spawnr-skills#5** — The `spawnr-mcp` skill says how to list open work nobody holds: `spawnr_list_tasks({"status": "open", "unassigned": true})` (not with `assignee_id`), or take the next one with `spawnr_claim_task({})`. `total_count` is the number of matching tasks across all pages (AgentTaskTracker#2361).
- **spawnr-skills#22** — The skills install with `npx skills add spawnrapp/spawnr-skills`. `spawnr-protocol` is now a skill folder with its own `SKILL.md`, so an installer that finds skills by `SKILL.md` brings the shared rules along; a single-skill install must name it too (`--skill spawnr --skill spawnr-protocol`). `setup.sh` installs the CLI from PyPI (`pipx install spawnr`, else `uv tool install spawnr` or `pip install --user spawnr`) and starts `spawnr login`; it installs and configures the MCP server only with `SPAWNR_LOCAL_DEV` set, because the MCP packages are published at launch. The `spawnr` skill's Prerequisites and the examples install the CLI from PyPI, name no server, and give `SPAWNR_API_URL` as the CLI's server override (it was documented as `SPAWNR_BASE_URL`). The README leads with the `npx` install. With `SPAWNR_LOCAL_DEV` set, the MCP config it writes now defaults `SPAWNR_BASE_URL` to `http://localhost:8000`, the MCP server's own default, instead of a host that does not resolve. The repo has a `LICENSE`: MIT, the same as the published `spawnr` CLI.
- **spawnr-skills#20** — The `spawnr` skill has a "Dispatched by the runner" section for an agent started by `spawnr runner` (`SPAWNR_TASK_ID` set): deliver (a PR for code, `spawnr task attach add` for the allowed file types), hand back to `in_review` with a summary, `spawnr task block` when stuck. The skill description now also activates on a runner-dispatched task.
- **AgentTaskTracker#2535** — An agent key may comment only on a task it holds or is mentioned on (epic 031 D7); any other task is 403 `AGENT_NOT_PERMITTED`. The skills teach the rule and `mention_agent_ids` on `spawnr_comment_on_task`. ([#19](https://github.com/spawnrapp/spawnr-skills/pull/19))

## 1.0.0 — 2026-10-18

The agent-flow release (epic 031): the three skills share `skills/spawnr-protocol/PROTOCOL.md`; install it beside any skill.

- **US-031.1** — The skills teach what an agent key may no longer do: delete a task, write an epic, create a top-level task, reassign one, or add a dependency between tasks it neither holds nor created. A claim on a task someone else holds is 409 `already_claimed`, and a reassign is 403 `agent_cannot_reassign`; neither is retried. ([#3](https://github.com/spawnrapp/spawnr-skills/pull/3))
- **US-031.2** — Roles, areas and needs on an agent's capabilities, and 409 `capability_mismatch` when a claim lacks one. ([#4](https://github.com/spawnrapp/spawnr-skills/pull/4))
- **US-031.3** — No skills change. Flows are defined by a person in Settings; the agent-facing `flow` parameter is US-031.4.
- **US-031.4** — Choosing a flow while claiming (`flow`), and 403 `flow_not_allowed` when the flow is not open to agents. ([#7](https://github.com/spawnrapp/spawnr-skills/pull/7))
- **US-031.5** — Handoffs between flow phases: five fields on every phase change, 422 `handoff_required`, 409 `role_mismatch`, and the openclaw `handoff` command. ([#8](https://github.com/spawnrapp/spawnr-skills/pull/8))
- **US-031.6** — The agent loop is wait, act, hand off, on the agent inbox (`spawnr_wait_for_updates`, `spawnr inbox wait`, `poll_tasks.py`). It also folds in US-9.2.100 (`spawnr inbox wait`, [#10](https://github.com/spawnrapp/spawnr-skills/pull/10)) and #2434: a `task.created` for a task already assigned to you is yours, not an offer ([#12](https://github.com/spawnrapp/spawnr-skills/pull/12)). ([#9](https://github.com/spawnrapp/spawnr-skills/pull/9))
- **US-031.7** — Proposals: an agent adds work as a pending subtask, and 409 `proposal_not_approved` when it claims one early. ([#6](https://github.com/spawnrapp/spawnr-skills/pull/6))
- **US-031.8** — Caps, Advisor gates and escalation, and the workspace pause. `blocked_by_cap` (AgentTaskTracker#2437) is documented in US-031.9 PR 2. ([#11](https://github.com/spawnrapp/spawnr-skills/pull/11))
- **US-031.9** — The skills moved to this repo ([#1](https://github.com/spawnrapp/spawnr-skills/pull/1)). The protocol release adds the shared protocol with an Advisor playbook and a table of every refusal code with what to do, the Coder to Tester worked examples for `spawnr-mcp` and `openclaw`, and `scripts/check_links.py`. `poll_tasks.py` takes `--timeout` instead of `--interval` (the old name still works), and its handler now gets the task detail, so it can read the pinned handoff.
